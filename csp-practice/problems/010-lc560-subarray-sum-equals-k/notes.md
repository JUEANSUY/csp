## 题意

给定一个整数数组 `nums` 和整数 `k`，统计和等于 `k` 的连续子数组个数。

子数组必须是连续的一段。

## 我的思路

先写了暴力版：

- 枚举每个起点 `i`。
- 从 `i` 开始向右累加 `sum`。
- 每当 `sum == k`，答案加一。

暴力版逻辑正确，但时间复杂度是 O(n^2)，LeetCode 会超时。

最终使用前缀和 + 哈希表。

维护当前前缀和 `sum`。如果以前出现过某个前缀和 `oldSum`，并且：

```text
sum - oldSum = k
```

那么：

```text
oldSum = sum - k
```

所以每次扫到一个新位置时：

1. 更新当前前缀和 `sum += nums[i]`。
2. 查询之前出现过多少次 `sum - k`。
3. 把这些次数加到答案里。
4. 记录当前 `sum` 出现次数加一。

核心逻辑：

```c
add(0);

for (int i = 0; i < numsSize; i++) {
    sum += nums[i];
    count += get(sum - k);
    add(sum);
}
```

`add(0)` 表示还没读取任何数时，前缀和 0 出现过一次。它用于统计从数组开头开始、和正好为 `k` 的子数组。

## 哈希表实现

使用开放寻址哈希表：

- `keys[h]`：存前缀和。
- `values[h]`：这个前缀和出现次数。
- `used[h]`：这个位置是否被使用。

哈希函数要处理负数：

```c
int h = key % MOD;
if (h < 0) {
    h += MOD;
}
```

冲突时向后找下一个位置，到末尾后回到 0。

## 关键边界

- 数组中有负数。
- 数组中有 0。
- 多个不同子数组都满足条件。
- `k = 0`。
- 单元素数组。
- 从下标 0 开始的子数组和等于 `k`。

## 错误记录

- 暴力版里一开始写了 `sum > k` 就停止，但数组中有负数时不成立。
- 暴力版里一开始找到 `sum == k` 就停止，但后面可能还有 0 或负数形成新的合法子数组。
- 哈希表 `get` 函数里曾写成 `used[key]`，这是错误的，应该使用哈希位置 `used[h]`。
- 全局数组只会在程序启动时自动清零一次，LeetCode 可能多次调用函数，所以在 `subarraySum` 开头清空 `used` 和 `values` 更稳。

## 复杂度

- 时间复杂度：O(n)，不计清空哈希表的固定开销。
- 空间复杂度：O(n)。

## 可优化点

当前实现每次调用会清空整个哈希表：

```c
for (int i = 0; i < MOD; i++) {
    used[i] = 0;
    values[i] = 0;
}
```

这很稳，但 runtime 会多一些。更快的写法可以用时间戳数组避免清空，不过实现复杂度更高。当前版本对 CSP 备考已经够用。

## 本地输入格式

```text
n
nums[0] nums[1] ... nums[n-1]
k
```

样例：

```text
3
1 1 1
2
```

输出：

```text
2
```

## 复盘

这题不能用简单滑动窗口，因为数组中有负数。核心公式是：当前位置前缀和为 `sum` 时，需要找之前出现过多少次 `sum - k`。
